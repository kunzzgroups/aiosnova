# AIOS Sidebar & Navigation Standard

> 文件编号：17
> 文件名称：Sidebar & Navigation Standard
> 适用范围：AIOS 全部 Web 前端应用外壳（App Shell）、Admin、Super Admin、业务模块
> 适用对象：Cursor、AI Agent、Frontend Developer、UI/UX Designer
> 前置规则：必须遵守《01 产品原则》至《16 Identity Organization Standard》，视觉令牌服从《04 UI 设计系统》
> 前端技术：React + Vite + TypeScript + React Router
> 核心目标：导航层级唯一、位置稳定、交互一致、可无痛扩展

---

# 1. 文件目的

定义 Sidebar 与 Navigation 的**唯一实现规范**。

Navigation 是产品信息架构的投影，不是文件目录树，也不是每个模块各自发挥的地方。任何新增项目（一级分类 / 二级模块 / 三级页面）都必须按本文件做，**不得为单个项目写专属样式或专属渲染分支**。

## 1.1 代码位置

| 关注点 | 文件 |
|--------|------|
| 导航数据（唯一来源） | `src/navigation/sidebarNav.ts` |
| 渲染与交互 | `src/components/navigation/Sidebar.tsx` |
| 样式与令牌 | `src/components/navigation/Sidebar.css` |
| 图标 | `src/components/navigation/SidebarIcons.tsx` |
| 顶栏公司 Tab | `src/layouts/CompanyTabs.tsx` |
| 顶栏模块 Tab | `src/layouts/ModuleTabs.tsx` |
| 顶栏 Tab 共用样式 | `src/layouts/TopTabs.css` |
| 公司切换状态 | `src/stores/companyStore.ts` |

## 1.2 历史教训

本规范中的「实现约束」一节全部来自真实 Bug，不是理论。

曾经存在两套特例：`hideLabel`（某 Section 不显示一级名）与 `INLINE_SECTION_IDS`（某 Section 点击向下内联展开）。它们导致 Sidebar 出现三种交互形态、代码里出现不可达分支，最终被全部删除。**结论：形态只能由数据决定，不能由特例决定。**

# 2. 信息架构：固定三层

```text
Section（一级分类）
└── Module（二级模块）
    └── Page / Link（三级页面）
```

数据只写在 `sidebarNav.ts` 的 `sidebarSections`。

```ts
export type SidebarSection = {
  id: string          // kebab-case，全局唯一
  label: string       // 一级行显示名
  children: SidebarNode[]
}

export type SidebarNode = SidebarLink | SidebarGroup
// SidebarGroup.children 只能是 SidebarLink
// SidebarLink = { kind: 'link'; id; label; path }
```

## 2.1 规则

1. **path 与 id 由 helper 生成，禁止手写。** `link()` / `group()` / `moduleGroup()` 按 label slug 化并拼 path；id 为 path 去掉前导 `/` 后把 `/` 换成 `.`。
   * `/customer-revenue/crm` → id `customer-revenue.crm`
   * `/customer-revenue/crm/leads` → id `customer-revenue.crm.leads`
2. **Module 不得嵌套 Module。** 只允许 Section → Module → Link 三层。
3. **一级行名称不要和二级重复。** 一级直接写模块名（`Dashboard`、`AI`、`Customer & Revenue`），不要再套一层同义分类名。
4. **Permission / 可见性过滤走 `filterSidebarSections()`**，不要写进渲染组件。
5. 当前一级分类：`Dashboard`、`AI`、`Customer & Revenue`、`Operations`、`Finance & People`、`Work Management`、`Platform`、`System`、`Platform Admin`。

# 3. 交互模型：一级行只有两种形态

渲染器依据 **该 Section 下 Module 的数量** 自动决定形态，**不需要也不允许写专属分支**。

| Section 下 Module 数 | 展开态一级行 | 二级去向 |
|----------------------|--------------|----------|
| **> 1** | 图标 + 名称 + 右向 chevron `›`；悬停/点击 → **右侧面板** | 面板内列出 Module；点某个 Module → 跳到它的**第一个页面** |
| **= 1** | 图标 + 名称，**无 chevron 的普通链接** | 直接跳到该 Module 的第一个页面，没有面板 |

三级页面（Module 的子页面）**不在 Sidebar 里展开**，统一由顶栏 Tab 呈现（见第 4 节）。

## 3.1 Active 规则

* 当前路由所属的 Section：一级行使用 `.is-open` 高亮（品牌色实心）。
* 当前路由所属的 Module：在右侧面板内高亮。
* 判断方式统一用 `findModuleByPath(pathname)` 推导，**不要另外维护一份展开状态集合**。

## 3.2 折叠态

| 行为 | 结果 |
|------|------|
| 显示 | 每个 Section 只显示图标；图标本身是**链接**（`NavLink`） |
| **点击图标** | **直接跳转到该 Section 的第一个页面**（`firstLinkInSection`，深度优先取第一个 link）；已在该 Section 内则 `preventDefault`，不跳回首页、不产生重复历史 |
| 当前 Section | 对应图标加 `is-active`（用 `findModuleByPath(pathname).section.id` 判定），样式用 `--sidebar-active` / `--sidebar-active-ink` |
| 悬停（Section 下 Module > 1） | 弹右侧模块面板（用于选具体页面） |
| 悬停（Section 下 Module = 1） | 只弹名称胶囊（tip） |
| 提示文案 | 用 `aria-label`，**不要用原生 `title`**（否则与自绘提示重复出现） |
| 没有页面的 Section（无 link） | 退回旧行为：点击展开 Sidebar |

展开 Sidebar 由品牌区的折叠开关（`sidebar__collapse-toggle`）负责，**不再**占用一级图标的点击。

折叠态还必须保留 GROUP COMPANIES 的图标入口（公司切换器的唯一入口）。

# 4. 顶栏 Tab：三级导航的唯一去处

顶栏位于 App Header 下方，共两条 Tab 条，**共用同一套 `.top-tabs` 样式**。

| 条 | 组件 | 内容 | 作用 | 可见条件 |
|----|------|------|------|----------|
| 公司条 | `CompanyTabs` | 悬停预览的组 / **已点选待决定的组** / 激活公司所在组 | 切换当前公司 | 悬停预览中，或有点选待决定的组，或面板刚打开 |
| 模块条 | `ModuleTabs` | 当前路由所属 Module 的 Page | 切换 Module 内页面 | 有匹配 Module 时始终显示 |

## 4.1 规则

1. **两条 Tab 必须共用 `.top-tabs__tab` 基类，禁止另做变体。**
   Tab 元素有时是 `<a>`（React Router `NavLink`）、有时是 `<button>`。基类必须 reset 掉 UA 的 button chrome（`appearance` / `border` / `background` / `font`），否则 `<button>` 那条会带浏览器默认边框与灰底，看起来像另一套设计。
2. **选项少于 2 个时整条不渲染。** 没有可切换对象就不要出现。
3. **无分组归属的公司 → 公司条不显示任何选项。** 不得回退显示「上一个组」的公司。
4. 页面内**禁止**另造第三套 Tab / Pill 样式。
5. **公司条是三级选择器，不是常驻层。** 完整流程：
   ```text
   一级 侧栏 GROUP COMPANIES（悬停/点击）
     └ 二级 组（KUNZZ HOLDINGS…）  ← 点击 = 一步，不是决定
         └ 三级 公司（Acme Retail / Acme Wholesale…）← 出现在顶栏，点击 = 决定
   ```
   - 点二级后公司条必须**留着**，直到三级选完才卸载；点三级后立即 `return null`。
   - 理由：公司切换一天用不了几次，但常驻条每天要价一整行高（约 42px）。
   - 卸载用 `return null`，不是 `display: none`：不要把高度留在版面上。
   - 解析优先级（顺序不可颠倒）：
     1. `previewCompanyId`（悬停中）→ 该行所属组；悬停无组公司→ 空（规则 3）。
     2. `pinnedGroupId`（已点选的二级）→ 该组，面板收起也不消失。
     3. `panelOpen`（面板开着还没悬停任何行）→ 回退激活公司所在组。
6. **点二级必须同时写入 `pinnedGroupId`；点三级必须清空它。** 三级把 `pinnedGroupId` 重新钉住会造成「选完不收起」，而点二级不钉住会造成「点完就没了」，两个方向都错。
7. **可点击性由两个状态位保证**（都必须是 store 字段，不能各自持有）：
   - `stripHovered`：鼠标在公司条上。公司条在侧栏**之外**，没有它，指针还没走到公司条，`POPOVER_HIDE_DELAY_MS` 一到面板就收了，条会在鼠标底下消失——表现为「点不动」。
   - 外部 `pointerdown` 判定必须把 `[data-company-strip="true"]` 排除，否则点击会在 `pointerdown` 阶段先收起面板 → 条卸载 → `click` 永不触发。

## 4.2 公司条的状态来源

公司切换状态集中在 `companyStore`：

```text
companyId          当前激活公司
previewCompanyId   悬停预览的公司（null = 没有悬停）
pinnedGroupId      已点选、等三级决定的组（null = 没有待决定的选择）
panelOpen          GROUP COMPANIES 面板是否打开
stripHovered       鼠标是否停在公司条上
companies          启用中的公司
groups             公司组
```

| 操作 | 写入 | Tab 结果 |
|------|------|----------|
| 打开 / 悬停 GROUP COMPANIES 面板 | `panelOpen = true` | 出现，显示激活公司所在组 |
| 悬停一个组（二级） | `previewCompanyId = 该组第一个成员` | 该组的公司 |
| 悬停无组公司 | `previewCompanyId = 该公司自身` | 空（整条不渲染） |
| **点选一个组（二级）** | `pinnedGroupId = 该组` + 激活公司切到该组第一家 + 面板收起 | **该组公司继续留着**，等三级决定 |
| **点选公司条上的公司（三级）** | 切换激活公司 + `pinnedGroupId = null` + `panelOpen = false` | **整条卸载** |
| 点选独立公司（无组） | `pinnedGroupId = null` | 整条卸载（无组可显示） |
| 鼠标进入公司条 | `stripHovered = true` | 保持不变，面板与预览不收起 |
| 鼠标离开公司条 | `stripHovered = false` | 面板收起；无 `pinnedGroupId` 时整条卸载 |
| 鼠标移开侧栏面板 | `previewCompanyId = null` | 回落到 `pinnedGroupId` 的组 |

`setPanelOpen(false)` **必须同时把 `stripHovered` 复位为 false**：公司条被卸载后不会再派发 `mouseleave`，残留的 `true` 会让 `scheduleHideFlyout` 永久跳过收起计时器，面板卡住不再自动关闭。

Sidebar 与顶栏**必须读写同一份 store**，不要各自持有 state。

# 5. 尺寸与令牌

| 变量 | 值 | 用途 |
|------|-----|------|
| `--sidebar-width` | `19.5rem` | 展开宽度 |
| `--sidebar-collapsed-width` | `4.35rem` | 折叠宽度 |
| `--sidebar-flyout-width` | `14.5rem` | 右侧面板宽度 |
| `POPOVER_HIDE_DELAY_MS` | `320` | 悬停浮层延迟收起（毫秒） |

`POPOVER_HIDE_DELAY_MS` 不得随意调小：鼠标需要从一级行移动到右侧面板或顶栏 Tab，延迟过短会来不及点，表现为「面板闪一下就没了」。

新增尺寸应优先复用上述变量与《04 UI 设计系统》的 Design Token，禁止硬编码一次性数值。

# 6. 实现约束（踩坑清单）

违反以下任意一条都会产生 Bug，均为已发生问题。

1. **右侧面板必须渲染在 `.sidebar__nav` 之外。**
   `nav` 有 `overflow-y: auto`，面板放进去会被裁掉。面板应作为 `.sidebar-shell` 的子节点（`<aside class="sidebar-flyout">`），与 `<aside class="sidebar">` 平级。
2. **面板的 `left` 必须区分展开 / 折叠：**
   ```css
   .sidebar-shell--collapsed .sidebar-flyout { left: var(--sidebar-collapsed-width); }
   ```
   只写 `left: var(--sidebar-width)` 时，折叠态面板会飞出屏幕外。
3. **面板的 `top` 只在「打开它的那一行」测量一次。**
   不要在下级条目悬停时重新测量，否则面板会跟着鼠标上下移动。
4. **浮层必须互斥。** 公司面板 / Section 面板 / 名称胶囊，同一时刻最多存在一个。
5. **折叠态的 `display: none` 要留神。**
   `.sidebar--collapsed .sidebar__context` 之类会整块隐藏；需要折叠态仍可见的元素（如 GROUP COMPANIES 图标入口）必须放在被隐藏容器**之外**。
6. **图标必须登记。**
   一级用 `SECTION_ICONS[sectionId]`，二级用 `MODULE_ICONS[moduleLabel]`。未登记会 fallback 成 `IconDot` / `IconFolder`，视觉上很突兀。
7. **不要为某个 Section 写专属渲染分支。**
   形态**只能**由 Module 数量决定（见 1.2 历史教训）。
8. **禁止在 Sidebar 内联展开列表。**
   展开会把它下面的所有一级项往下挤，导航位置不稳定、鼠标需要重新定位。
9. **点击已在当前的直达行不要跳转。** 避免把重复的历史记录压入 history 栈。

# 7. 新增导航项 Checklist

## 7.1 新增一个 Section（一级分类）

1. 在 `sidebarNav.ts` 的 `sidebarSections` 增加一项：`id` 用 kebab-case，`label` 用最终显示名。
2. 在 `SECTION_ICONS` 注册一级图标。
3. 用 `moduleGroup()` / `group()` 声明 Module 与 Page。
4. **不需要**改 `Sidebar.tsx` / `ModuleTabs.tsx`：Module 数量 > 1 自动得到右侧面板，= 1 自动成为直达链接。

## 7.2 新增一个 Module（二级模块）

1. 在所属 Section 的 children 增加 `group(label, basePath, [...pages])`。
2. 在 `MODULE_ICONS` 注册二级图标。
3. 该 Module 的**第一个页面会成为它的落地页**（右侧面板的行、直达行都指向它）。
4. 顶栏模块 Tab 自动按该 Module 的页面列表生成，不需要手动维护。

## 7.3 新增一个 Page（三级页面）

1. 在该 Module 的 `items` 数组加 label 即可，path 自动生成。
2. 页面组件挂到 `src/routes/router.tsx`；未实现时可先用 `ModulePlaceholderPage`。
3. 确认它出现在顶栏模块 Tab 中（应自动出现）。

# 8. 禁止事项

* 禁止不同页面切换完全不同 Sidebar 风格（结构、字号、配色、间距必须一致）。
* 禁止在页面内自建导航（第二套 Sidebar、第二套 Tab 样式）。
* 禁止手写 path / id，禁止跳过 helper 拼接字符串。
* 禁止为单个项目新增硬编码尺寸（用 5 节的令牌与 Design Token）。
* 禁止用 `title` 属性作为唯一的可访问名称（用 `aria-label`）。
* 禁止在改动后留下不可达代码分支与未引用 CSS：**改完必须删干净**。

# 9. 自检清单

改动 Sidebar / Navigation 后逐项确认：

* [ ] 展开态：一级行只有「带 `›` 的面板行」与「无 `›` 的直达行」两种形态。
* [ ] 折叠态：所有一级图标都在；需要折叠态可见的入口没有被 `display: none` 吃掉。
* [ ] 右侧面板贴在侧边栏右侧；折叠态不飞出屏幕。
* [ ] 悬停下级条目时面板**不移动、不消失**。
* [ ] 鼠标从一级行移动到面板的过程中，面板不会被提前收起（`POPOVER_HIDE_DELAY_MS` 足够）。
* [ ] 顶栏 Tab 与 Sidebar 的当前状态一致；选项 < 2 时整条消失；无组公司不显示任何选项。
* [ ] 键盘可达：`Tab` 能聚焦一级图标 / 行，`Esc` 能关闭浮层，点击面板外部能关闭浮层。
* [ ] 没有留下不可达的渲染分支、未使用的 state、未引用的 CSS 类或未引用的图标导出。
* [ ] `tsc --noEmit` 与 `vite build` 通过。
